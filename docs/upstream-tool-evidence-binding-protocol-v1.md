# 上游 ToolResult 证据绑定协议 v1

本协议规定派生数值工具如何消费已经登记的 `ToolResult`。它补足“UUID 格式合法”并不等于
“输入数值可追溯”的边界：调用方、UI 与 LLM 不能携带可被替换的 SOH、RUL、工况、区间或
批次决策数值进入派生工具。

## 适用范围

直接数据工具可以接收经过来源核验的原始记录和 `ProvenanceRecord`，例如数据质检、原始数据
适配和受控特征提取。任何消费模型、特征、预测、区间、物理核验或决策结果的**派生工具**
必须按本协议工作。

## 强制绑定规则

1. 派生工具输入只包含一个或多个上游 `result_id`、非数值控制项和请求元数据；不能重复接收
   已由上游产生的业务数值或其来源记录。
2. 每个 `result_id` 必须由 `AuditLedger.resolve_registered_result()` 解析。不得访问账本私有
   状态，也不得仅检查 UUID 格式。
3. 工具必须检查上游 `tool_name`、版本兼容性和 `values` 中的受控载荷类型；随后用对应
   Pydantic 契约重新解析载荷。
4. 预测器、校正器和决策器的数值输入只能由上述已解析载荷构造，不能由调用方拼装或覆盖。
5. 派生 `ToolResult.provenance` 仅能由已解析上游结果的来源链派生；调用方不能提交独立
   provenance 覆盖它。
6. 派生结果必须保留所有实际消费的上游 `result_id`、模型/数据/特征/划分版本和输入哈希。
7. `ToolResult.created_at` 表示工具实际执行的 UTC 时间。观测时间、请求时间或采集时间属于
   上游载荷，不得伪装为结果生成时间。

## 标准载荷形态

上游结果在 `values` 中使用如下稳定外层：

```json
{
  "artifact_type": "qualified.artifact.type.v1",
  "artifact": { "...": "由该载荷契约定义" }
}
```

载荷应包含其消费方需要的身份、版本、数值和边界条件。例如轨迹预测的输入载荷至少包含
`dataset_id`、`cell_id`、`cutoff_cycle`、截断点及以前的观测周期与 SOH、工况、特征/划分/
数据版本。在线校正分别消费已登记全局轨迹载荷与 `NEWLY_OBSERVED` 观测载荷。

## 失败与降级

以下情况必须在数值模型调用前拒绝：结果未登记、上游工具名不匹配、载荷类型未知、载荷字段或
版本不匹配、载荷含截断点后数据、来源链缺失，或输入含有未声明的数值字段。域外、低质量或
观测不足的已绑定数据由领域数值工具显式返回 `RECHECK`、`DOWNGRADE` 或 `REJECT`，不得静默
填补或制造乐观结果。

## 迁移要求

既有只携带 `upstream_result_ids` 加自由数值输入的工具必须迁移到本协议后才能作为 Agent、API、
MCP、Next.js 或 Streamlit 的正式共享能力暴露。迁移期间可保留底层数值模块用于研究实验，但
不得将未绑定包装器注册到默认工具表。

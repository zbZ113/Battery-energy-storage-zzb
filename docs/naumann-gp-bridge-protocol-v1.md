# Naumann 条件观测到主动试验 GP 输入桥接协议 v1

## 1. 目的与边界

本协议定义如何将已完成来源核验的 Naumann 循环老化或日历老化**条件级观测**，一对一转换为主动试验高斯过程（GP）可消费的 `ExperimentObservation`。实现位于：

```text
src/quanxin_life/experiments/naumann_bridge.py
```

该桥接层是来源保真中间层，不是 `ToolResult` 生成器，也不产生寿命、SOH、RUL、置信区间或物理仿真数值。后续受治理的工具层必须为任何面向用户的数值结果建立独立的 `ToolResult` 与审计记录。

桥接仅服务于公开实验室数据上的工况级主动试验回放与方法验证；不得将桥接产物表述为济南企业、海辰储能或其他工业储能电芯的真实生产数据。

## 2. 允许输入

仅允许以下已解析的契约对象进入桥接函数：

- `CycleMatrixObservation`：来自 `NAUMANN_CYCLE` 的显式循环条件观测；
- `CalendarCapacityObservation`：来自 `NAUMANN_CALENDAR` 的显式日历老化容量观测；
- `NaumannGpBridgeMapping`：经人工审查、版本化的映射配置。

桥接器不会读取 MAT、XLSX、CSV 或自由文本；原始文件解析、布局判断与字段提取必须由对应的数据适配器完成。桥接器也不得从 `condition_id`、文件名、协议描述或其他字符串中推断 DOD、充电倍率、放电倍率、资源成本或时间。

## 3. 映射配置的强制声明

`NaumannGpBridgeMapping` 必须同时声明以下内容：

1. `mapping_version`：人工审查映射的版本标识；
2. `target_transform`：源指标名称、目标名称、可审查的指标变换，以及速率目标的显式分母量纲；
3. `resources`：`duration_hours`、`equipment_cost`、审查说明与证据引用；
4. 若使用日历数据，逐条件声明 `calendar_conditions` 中的 DOD、充电倍率、放电倍率、科学使用说明和证据引用。

`ExperimentObservation` 的资源字段属于主动试验回放的显式资源假设，不是 Naumann 原始测量的属性。由于源适配器不包含实验预约时长或设备成本，映射缺少 `resources` 时必须拒绝，不得写入默认值、占位值或隐式常数。

日历老化记录天然没有循环 DOD 和 C-rate。只有映射为同一 `condition_id` 同时声明完整循环字段、科学用途及证据引用时，才允许将其作为工况比较输入。此行为仅表示“经审查的比较/代理条件”，不能把日历观测重新解释为真实循环寿命试验；没有映射必须显式拒绝。

## 4. 目标变换与禁止行为

允许的 `TargetTransformMode` 如下：

| 模式 | 允许源指标 | 计算 |
|---|---|---|
| `direct_metric_value` | 容量或内阻 | 保留原始指标值 |
| `relative_capacity_loss` | 容量 | `(参考容量 - 当前容量) / 参考容量` |
| `relative_capacity_loss_rate` | 容量 | 相对容量损失除以显式观测轴 |
| `relative_resistance_growth` | 内阻 | `(当前内阻 - 参考内阻) / 参考内阻` |
| `relative_resistance_growth_rate` | 内阻 | 相对内阻增长除以显式观测轴 |

相对变换必须显式提供正的 `ReviewedReferenceMetric`；速率变换要求观测轴为正。桥接器不会自动选择首循环、均值、最大值或任何其他参考值。

相对变换的参考量不得是裸数值。`ReviewedReferenceMetric` 必须声明正的参考测量值，并且只能采用以下两种可审计来源之一：

- `source_observation`：同时提供来源观测标识、来源 SHA-256 与来源 URI；
- `reviewed_configuration`：同时提供人工审查说明和证据引用。

参考量对象会原样保留在桥接输出的 provenance 中。它不是新的源观测，也不会代替源文件中的测量；其作用是让相对容量损失或相对内阻增长的分母可追溯。

速率模式还必须声明 `rate_denominator_basis`。允许的规范量纲仅为：

- `equivalent_full_cycles`：来自循环适配器的等效满循环观测轴；
- `time_h`：来自循环适配器的时间轴或日历适配器的存储时间轴。

桥接时会严格比较声明量纲和源观测轴：不匹配即拒绝。每个映射一次只允许一个目标名称与一个分母量纲，因此不会在同一 GP 输入批次中静默混合“每等效循环”与“每小时”退化率。不同量纲的结果必须使用不同映射版本和不同目标名称。

桥接层严格禁止：

- 聚合多个源观测点；
- 插值、平滑、补齐或填充缺失条件；
- 从字符串或文件路径推断工况；
- 使用未经映射声明的资源时长或成本；
- 创建伪造的 `ToolResult`、模型版本或实验结果；
- 将 PyBaMM 或其他仿真结果混入该来源桥接路径。

每个输入观测只产生零个或一个桥接输出；校验失败即拒绝，绝不静默降级为人工默认条件。

## 5. 来源链与确定性标识

每条 `BridgedExperimentObservation` 同时保存 `NaumannGpProvenance`。来源记录至少包含：

- 源数据集与源条件标识；
- 确定性的源观测标识；
- 原始文件路径、SHA-256、布局版本与适配器版本；
- 桥接版本与映射版本；
- 日历条件的科学使用说明和证据引用（若适用）；
- 资源审查说明和资源证据引用。

Naumann 当前适配器不提供原始行/列主键，因此桥接层会生成派生源观测标识。该标识由数据集、条件、源文件 SHA-256、布局版本、适配器版本、观测轴名称和值、指标名称和值的规范化哈希生成。它不是原始数据集提供的主键，也不是面向终端用户的结果 ID；它用于检测完全相同的桥接输入并保证每条可区分源测量与 GP 输入的一对一审计关系。

## 6. 下游使用约束

桥接输出可提供给 `gp_active` 的训练、回放和候选试验策略，但下游必须：

- 保留桥接来源链并把映射版本纳入实验配置；
- 将公开实验室条件与目标域工业工况明确区分；
- 在域外数据或未重校准工况上显示降级警告；
- 单独评估随机、均匀与主动策略，不通过选择标签泄漏制造优势；
- 不依据本桥接层直接生成批次入组、复检、降级或经营决策。

该协议与 `docs/active-experiment-protocol-v1.md`、数据契约及项目 `AGENTS.md` 共同生效。发生冲突时，以更严格的来源保真、数据隔离和数值审计要求为准。

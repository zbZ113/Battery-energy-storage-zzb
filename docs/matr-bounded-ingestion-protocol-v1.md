# MATR 受控早期循环摄取协议 v1

## 目的

MATR 四个公开批次体积较大。首轮研究不应将全部采样点、全部电芯和全部循环一次性物化为内存或 Parquet。`load_matr_batch` 从适配器 `matr-hdf5-v1.1.0` 起支持经过来源核验的受控摄取：

- 精确选择待处理的原始电芯；
- 仅物化早期预测截断点以前的循环采样记录；
- 保留完整的原始文件 SHA-256、官方寿命标签和选择参数，供后续数据卡、特征泄漏审计与实验复现使用。

这只减少本进程和下游产物的规模；HDF5 文件仍须存在，且在打开前必须根据 `RawFileManifest` 完整校验 SHA-256。它不是跳过来源核验或对 26 GB 原始文件做不可信的局部读取。

## 调用契约

```python
load_matr_batch(
    path,
    manifest,
    batch_index=1,
    time_unit="seconds",
    selected_raw_cell_ids=("b1c0", "b1c1"),
    max_cycle_index=49,
)
```

- `selected_raw_cell_ids` 是原始 HDF5 批次中的精确标识符集合，格式为 `b{batch_index}c{cell_index}`。例如 `b1c0`；不能传单个字符串、重复标识符或不存在的标识符。
- `max_cycle_index` 是**包含上界**：`49` 只物化循环索引 `0..49`。如果实验协议定义“使用前 50 个、从 0 开始编号的循环”，应传 `49`。若协议中的截断点本身采用循环索引 `k`，则传 `k`，且仅使用 `cycle_index <= k` 的观测。
- 参数未指定时保持旧行为：读取该批次全部电芯与全部循环。
- `skip_cycle_zero=True` 只会在已选择且未超过上界的范围内跳过索引 0；调用者必须在实验配置中记录该选择。

适配器将 `selected_raw_cell_ids`、`max_cycle_index`、`batch_index`、`time_unit` 和 `skip_cycle_zero` 写入每个 `CellMetadata.ingestion_parameters`。它们是审计输入，不是可供模型训练的寿命特征。

## 数据与泄漏边界

1. 适配器可读取官方 `cycle_life`，但该值只作为保留的官方标签；早期特征提取器不得将其、EOL 后信息或截断点后的采样点输入模型特征。
2. `max_cycle_index` 的选择须由实验配置固定为 20、50、100、150 循环设定之一，不能根据测试电芯表现临时增大。
3. 后续划分仍按 `cell_id` 完全隔离；先选择电芯再摄取不改变训练、验证、校准和测试的隔离要求。
4. 原始 MATR 数据是公开实验室 LFP/石墨电芯数据，报告中不得表述为济南或企业现场储能大电芯数据。
5. 若选定的截断范围在 `skip_cycle_zero` 后没有剩余有效诊断记录，质量检查必须显式降级或阻断，不能静默补零。

## 建议的增量执行方式

1. 先下载并核验一个官方 MATR 批次，而非同时下载四个批次。
2. 从固定 `SplitManifest` 中选取少量代表性 `raw_cell_id`，按一个截断点进行转换与特征测试。
3. 审计生成的 JSON 元数据和 Parquet 清单后，再扩大到同一批次其余已分配电芯。
4. 只有在基线、混合退化模型和 Conformal 流程确认可复现后，再评估是否需要其他批次；不要为了“全量”而占用本地存储。

原始目录 `data/MATR/` 继续被 Git 忽略。进入版本控制的仅是来源清单、SHA-256、处理配置、固定划分、数据卡、代码和可再生成的受控产物清单。

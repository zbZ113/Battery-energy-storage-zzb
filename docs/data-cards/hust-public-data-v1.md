## 2. 当前审计做了什么

- 校验外层 ZIP 的大小与 SHA-256；
- 检查中央目录、压缩方法、成员路径、大小、压缩比和文件类型；
- 对每个 `.pkl` 成员以不透明字节流方式计算 SHA-256；
- 不调用 `pickle.load`，不提取到转换目录，不执行成员中的 Python 对象；
- 生成候选冻结清单，但候选清单不能直接授权转换；
- 只有人工批准后的清单再次全量复核成功，审计状态才允许变为 `ready_for_conversion=true`。

## 3. 当前尚未确认的内容

在隔离转换和字段审核完成之前，不能确认：

- 77 个文件是否各自对应 77 个有效电芯；
- pickle 内部字段、单位、循环编号、容量、温度、SOH 或 EOL 标签；
- 每个对象是否安全、完整且满足项目统一数据契约；
- 是否已经形成可信 Parquet、固定电芯划分或模型训练输入；
- HUST 与海辰储能电芯、储能电站 15–25 年运行或工业质保之间存在直接等价关系。

## 4. 对外表述边界

允许表述：

> 项目已对一个登记为 HUST Mendeley v2 的本地 ZIP 快照完成不透明字节静态审计，并生成等待人工批准的冻结清单。原始 pickle 尚未进入主应用、正式服务器或训练环境。

禁止表述：

- “HUST 数据已经安全转换完成”；
- “已经验证 77 个电芯的 SOH/RUL”；
- “已经完成 HUST 模型训练或跨域实验”；
- “该数据来自海辰储能”或“可直接代表海辰工业电芯”；
- “许可证已在 2026 年 7 月 16 日在线重新确认”。

## 5. 后续更新条件

只有依次完成以下工作，才能更新转换状态：

1. 项目负责人审核候选 inventory 的来源、压缩包哈希、77 个成员路径与哈希；
2. 生成带批准人和 UTC 时间的 `APPROVED` inventory；
3. 使用该 inventory 对原始 ZIP 再次全量静态审计；
4. 在无网络、无密钥、只读输入、非 root 的一次性隔离环境进行字段发现；
5. 人工审核字段和单位映射；
6. 逐文件转换为 Parquet 与 JSON 元数据；
7. 主项目重新验证安全产物、数据契约、哈希和 `cell_id` 划分。

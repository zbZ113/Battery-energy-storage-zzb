# 泉芯智寿前端方案 B 设计规格

- 日期：2026-08-02
- 状态：用户已选择并确认方案 B，正在按规格实施
- 视觉基准：`2026-08-02-quanxin-frontend-option-b.png`
- 适用计划：`docs/superpowers/plans/2026-08-02-quanxin-productization-master-plan.md` Task 1

## 1. 目标

将现有 Next.js 门户统一为“结果与运行状态同屏”的双栏分析工作台。登录、项目、数据选择、上传入口、电芯与 cutoff、固定九步 Agent、实时进度、RUL/SOH/Conformal、审计报告和下载必须形成一条连续路径。

本次只改变前端的信息组织、视觉层级、响应式布局和状态表达，不改变 `quanxin_life.core` 契约，不在浏览器计算业务数值，不为尚未存在的服务端能力伪造成功结果。

## 2. 不可违反的可信边界

1. RUL、SOH、Conformal、阈值比较和报告结论只展示有效 `ToolResult` 的服务端签发值。
2. 没有有效结果时，图表和指标区显示“等待 ToolResult”，不得放入示例曲线或示例数值。
3. 前端只做契约校验、身份一致性校验和坐标映射，不重新计算预测、区间或判断。
4. 警告、缺测、域外、身份不一致和加载失败必须在对应结果旁显式展示。
5. 浏览器不读取 HttpOnly Cookie，不记录密码、完整用户提示或敏感原始数据。
6. 尚未接入的上传、目录和导出接口使用明确的不可用状态，不用本地假数据模拟完成。

## 3. 视觉方向

### 3.1 设计语言

- 主工作台采用顶部深墨绿导航、暖白页面和双栏内容区。
- 左栏承担数据选择、结果图表和报告阅读；右栏固定承担唯一主操作、九步运行状态和下载状态。
- 通过分隔线、留白和紧凑标题建立层级，不使用玻璃拟态、渐变背景、发光边框、3D 电池或卡片墙。
- 页面区块采用无圆角或不超过 8px 的小圆角；嵌套内容通过分隔线而非卡片套卡片表达。
- 桌面端保持较高信息密度，移动端按任务顺序纵向排列。

### 3.2 颜色令牌

| 用途 | 颜色 |
| --- | --- |
| 主文字和顶部导航 | `#173C32` |
| 主操作 | `#2F6B57` |
| 悬停和选中 | `#255746` |
| 辅助图形 | `#8FA58D` |
| 次级强调 | `#7E8753` |
| 页面底色 | `#F5F0E2` |
| 内容表面 | `#FCFAF4` |
| 小面积高亮 | `#B49A55` |
| 边框 | `#D7D7C7` |

整体比例约为暖白 70%、绿色 25%、暗金/橄榄 5%。错误继续使用克制的红色，警告使用暗金背景和文字，不让状态只依赖颜色。

### 3.3 图表语义

- 观测值：深墨绿实线。
- 预测值：玉绿色实线。
- Conformal：灰豆绿透明带。
- 新观测：暗金或橄榄。
- 参考或模拟：中性灰虚线，并明确标注其身份。

## 4. 全局结构

### 4.1 顶部导航

`AppShell` 从左侧栏改为方案 B 的横向顶部栏：品牌、分析工作台、数据中心、运行记录、报告中心、可信边界状态和账号操作。当前尚无目标路由的导航项以文字和图标显示“尚未开放”，不可产生死链。

桌面端顶部栏固定高度，内容区宽度使用响应式上限；移动端保留品牌、当前页面和菜单按钮，展开后显示同一组导航和退出操作。

### 4.2 流程条

项目作用域页面顶部显示六段流程：

`登录/项目 → 样例/上传 → 电芯/cutoff → 九步 Agent → 结果/报告 → 下载`

每段同时使用序号、文字和状态样式。流程条只表达导航与完成条件，不根据 URL 猜测业务完成状态；需要业务状态时必须来自服务端记录。

### 4.3 双栏工作区

- 桌面宽度不小于 1200px：左栏约 62%，右栏约 38%。
- 768px 至 1199px：上下两栏，主操作与当前进度排在结果区之前。
- 小于 768px：单栏；流程条横向可滚动，表格提供受控横向滚动，按钮文字不得被裁切。

## 5. 页面设计

### 5.1 登录与改密

登录页保留品牌和可信边界说明，但取消夸张渐变和超大标题。左侧为深墨绿品牌区，右侧为紧凑登录表单；移动端先显示表单。错误信息不暴露服务端细节，密码只在受控输入中存在。

改密页复用相同认证框架，明确“必须修改密码”状态和返回登录路径。

### 5.2 项目总览

项目页采用紧凑列表或网格，显示项目名称和真实创建时间。加载、空列表、401 和通用失败分别展示。项目列表失败时保留重新加载操作，不展示虚构项目。

### 5.3 项目工作台

项目工作台是方案 B 的主页面：

- 左上：数据来源选择，分为内置样例和上传入口。
- 左上右侧：冻结数据、电芯和 cutoff 的选择摘要。
- 左下：SOH、RUL、Conformal、审计报告四个视图标签；没有 ToolResult 时显示可信等待态。
- 右上：唯一主操作“启动全新九步 Agent”。
- 右中：固定九步实时进度、失败原因和审批状态。
- 右下：证据摘要与下载状态。

现有手工填写数据集 UUID 和结果 UUID 的操作保留为兼容入口，但降为“高级定位”；Task 3 的目录 API 接入后由真实目录选择取代。

### 5.4 上传

Task 1 只建立与方案 B 一致的上传入口和可信状态外壳。文件选择、解析、数据质量、冻结和失败状态均必须来自 Task 5 的正式上传契约。正式接口接入前，入口明确标注“上传能力尚未接入”，不接受文件后伪装成功。

### 5.5 九步 Agent 运行

运行页将 SSE 事件映射为固定九步列表和事件明细：

1. 冻结分析输入。
2. RUL 精度路线。
3. RUL 覆盖路线。
4. SOH 有限时域。
5. RUL 校准。
6. RUL Conformal。
7. SOH 校准。
8. SOH Conformal。
9. 审计报告。

运行状态必须来自 run record 和事件流。断线、重连、失败、取消、等待审批和终态均同时使用图标、文字和颜色。未知事件不解释为成功。

### 5.6 结果、报告和下载

结果区继续执行现有 `single-cell-analysis-contract` 身份一致性校验。通过后才显示服务端数值、轨迹、区间、模型/数据/特征版本、SHA-256、来源和警告。

报告原文继续由 React 转义显示。下载区只展示服务端确认可生成或已生成的格式；Task 6 接口完成前显示“待服务端提供”，不创建假文件或浏览器拼装业务报告。

### 5.7 校准页面

校准页面保留现有只读和创建能力，只调整到同一顶部导航、表格、状态和颜色体系。READY、失败和缺证据状态继续来自真实接口。

## 6. 组件边界

- `AppShell`：顶部导航、可信边界、账号操作和响应式菜单。
- `WorkflowRail`：六段产品流程，仅接收显式状态。
- `AnalysisWorkspace`：双栏骨架，不获取业务数据。
- `DataSourceSelector`：样例、上传入口和冻结状态。
- `AgentRunLauncher`：唯一主操作与创建错误，不计算结果。
- `NineStepTracker`：将受支持的 run/step 状态映射为九步列表。
- `AnalysisResultTabs`：SOH、RUL、Conformal 和报告的视图切换。
- `EvidenceDock`：ToolResult 身份、警告和下载状态。
- 现有 `SingleCellAnalysis`、`SohTrajectoryChart`、`EvidencePanel`、`ApprovalPanel` 保留业务校验职责，只重组展示结构。

共享组件只接收 `frontend/lib/types.ts` 或现有契约解码器输出，不新增字段不同但语义相同的 DTO。

## 7. 数据流和错误处理

1. 页面通过 `frontend/lib/api-client.ts` 请求后端，继续携带 HttpOnly Cookie。
2. API 返回记录后，契约解码或现有安全解析器先验证结构和身份。
3. 只有验证通过的数据进入展示组件。
4. SSE 只更新运行事件和状态；终态后重新读取 run record。
5. 单项 ToolResult 失败不抹去其他已验证结果，但必须在原位置显示失败。
6. 未配置 API、401、403/404、网络失败、SSE 断开和未知 payload 均有独立可理解文案。

## 8. 可访问性

- 正文和控件达到 WCAG AA 对比度。
- 所有图标按钮提供可访问名称和 tooltip。
- Tab、菜单、流程条和选择控件支持键盘操作与可见焦点。
- 状态不只依赖颜色，动态状态使用合适的 `aria-live`。
- 小屏幕不出现不可恢复的内容裁切或控件重叠。
- 动画遵守 `prefers-reduced-motion`。

## 9. 测试先行与实现顺序

每个行为变更先添加测试并确认因目标行为缺失而失败，再写最小实现：

1. 全局令牌、`AppShell` 和响应式顶部导航。
2. 项目总览和六段流程条。
3. 项目双栏工作台与唯一主操作。
4. 九步运行跟踪和 SSE 状态映射。
5. 结果标签、证据栏、报告与下载等待态。
6. 登录、改密、校准和高级定位入口的视觉统一。
7. 桌面和移动浏览器 Design QA。

不得改写已有测试来掩盖回归。测试用固定契约夹具验证展示规则，不把夹具业务数值放入生产 UI。

## 10. 验收标准

1. 选定 PNG 与桌面主工作台在布局、层级和配色上保持一致。
2. 所有现有路由使用统一视觉系统并覆盖加载、空、失败、等待和成功状态。
3. 页面主操作文案统一为“启动全新九步 Agent”，同一视口不存在第二个竞争性主操作。
4. 无 ToolResult 时不出现业务结果数值或伪造图形。
5. `1440 × 1024`、平板和手机视口无横向页面溢出、文字裁切或控件重叠。
6. Vitest、ESLint、TypeScript 和 Next.js production build 通过。
7. 浏览器完成登录到下载的可达性检查；尚未接入的后端能力停在明确不可用状态。
8. 根目录 `design-qa.md` 记录逐项证据，最终一行必须为 `final result: passed`。

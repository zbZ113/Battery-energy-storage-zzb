# 泉芯智寿 README 竞赛与产业叙事设计

## 一、目标

将仓库首页重构为同时服务竞赛评审、产业合作与技术使用者的项目入口。README 首先回答项目解决什么问题、AI 在哪里发挥实质作用、系统为何可信以及对新能源装备产业有何价值；随后提供可复现的数据、训练、服务和前端使用方式。

README 不承担风险台账或未完成事项清单的职责。工程约束、验证边界和后续实施计划继续由项目宪法、实验协议、数据契约和实施计划承载。

## 二、受众优先级

1. 华为杯及济南地方赛评审：快速理解创新、产业价值和可演示闭环。
2. 新能源装备产业合作方：理解研发试验、批次筛选、运行边界和决策价值。
3. 算法与工程成员：能够按照命令准备环境、运行训练、启动服务并执行质量门禁。

## 三、核心叙事

项目统一使用以下定位：

> 泉芯智寿——面向新能源装备产业的多智能体协同储能电芯寿命预测与退化感知决策系统。

主叙事由七项能力构成：

1. 真实公开电芯数据的版本化治理与电芯级防泄漏划分；
2. 面向三批 MATR 数据的单卡 A100 真实训练、验证、早停、断点恢复与五种子评价；
3. 早期寿命预测、单调退化轨迹、可信区间和在线校正；
4. Naumann 工况主动试验推荐与 PyBaMM 短期物理边界核验；
5. 受约束专业智能体、强类型工具和数值来源防火墙；
6. FastAPI、Celery、Next.js、Streamlit、MCP及工业接口组成的产品闭环；
7. 以安全回调、幂等事件处理和可追溯任务卡片为基础的飞书研发协同。

项目意义聚焦：

- 缩短长周期电芯研发反馈链；
- 提升批次筛选、复检和分级使用的证据质量；
- 将模型不确定性转化为下一步试验和运行决策；
- 将异常告警、复检任务、审批与报告送入研发团队日常使用的飞书协同空间；
- 为济南新能源装备、储能系统集成和智能制造提供可复制的AI示范。

## 五、表达原则

- 价值先于实现细节，技术证据紧随价值主张。
- 使用“已建立、已实现、支持、通过……产生”等工程表述，不使用空泛口号。
- 不把测试夹具、仿真结果或Smoke结果描述为正式模型性能。
- MATR官方cycle-life与统一EOL80始终分开。
- PyBaMM始终描述为短期响应与边界核验工具。
- LLM始终描述为任务理解、工具编排、解释和报告层，不生成SOH、RUL或置信区间。
- 所有正式数字均应来自带版本和来源记录的 `ToolResult`。
- 飞书卡片传递 `run_id`、`result_id`、任务状态和审批引用，不复制或改写模型数值。

## 六、使用指南设计

README 的命令必须直接来自仓库现有入口：

- Python 3.11与可选依赖安装；
- `deploy/foundation_api.py` 基础API；
- `frontend` 的 pnpm/Next.js命令；
- `workbench/streamlit_app.py` 科研工作台；
- `scripts/a100/train_dataset.sh` 三批MATR Smoke与正式训练；
- `POST /v1/integrations/feishu/events` 飞书安全事件回调；
- pytest、Ruff、mypy、前端lint/typecheck/test/build质量门禁。

原始数据不纳入Git。README列出三批MATR文件名、清单目录和数据准备原则，并引导使用者通过哈希清单验证，而不在首页复制大段内部安全流程。

## 七、飞书协同设计

README 将飞书描述为研发决策协同层，重点呈现：

- 通过 `POST /v1/integrations/feishu/events` 接收飞书事件；
- 使用时间戳、Nonce、SHA-256签名和验证Token鉴别回调；
- 通过数据库事件回执、租约令牌和幂等路由抵御重复投递；
- 通过任务引用卡传递 `run_id` 和 `result_id`，避免在消息层复制未经审计的工程数值；
- 将异常告警、批次复检、报告分发、人工审批和任务跟踪组织为可扩展协同工作流；
- 通过 `.env.example` 提供空白凭证配置，真实密钥只由运行环境或秘密管理器注入。

README 的使用指南包含安全回调装配方式、环境变量说明和沙箱验证入口。对机器人消息、多维表格、报告文档、复检任务和审批卡片采用“协同工作流”表述，并明确其数值来源仍由平台工具与审计链控制。
